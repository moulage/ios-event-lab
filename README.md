# iOS 埋点测试工作台

本机 Web 工具，通过 USB 读取唱吧 debug 包日志，解析 `sensor statitic -- event:` 埋点，提供筛选、规则校验、趋势和脱敏导出。不会修改 iOS App 或访问业务数据库。

## 网页版

网页入口：https://moulage.github.io/ios-event-lab/

网页版默认进入“实时采集”，也可切换为“离线导入”。两种模式都可查看事件流、按事件名/日志关键词筛选、详情属性筛选、时间排序与统计。

实时采集使用同一台 Mac 上的本机桥接服务：

1. 将 iPhone 通过 USB 连接并信任 Mac，运行下文的 `python3 server.py`。
2. 打开本机工作台 `http://127.0.0.1:8766`，复制“网页版连接码”。
3. **在同一台 Mac 的 Chrome 中**打开网页入口，粘贴连接码并点击“连接本机”；若浏览器提示访问本地网络，选择允许。
4. 选择设备、开始采集，操作 debug 包；网页每 2 秒读取一次本机脱敏日志。停止采集时点击网页上的“停止采集”。

连接码在本机服务重启后更新，网页版连接码只保存在当前页面内存中。网页版只访问 `127.0.0.1:8766`，不能通过另一台电脑直接读取这台 Mac 的 USB 设备。浏览器读取到的数据不上传 GitHub；原始日志仍保存在本机 `data/local-test/`。桥接接口只接受此网页来源和正确连接码，不开放远程清空。

离线模式可导入 `.log`、`.txt`、`.jsonl`、`.ndjson` 或本工具导出的 `.json`。导入的数据仅在当前浏览器内存中处理，不会跨刷新保留。单文件最大 10 MB，每个会话最多读取 100,000 行。GitHub Pages 只托管网页文件，本机 Python 服务负责 USB 采集和本地规则校验。公开仓库只包含源码、网页和测试，不包含 `data/` 里的设备日志或数据库。

## 启动

1. 安装 Xcode 命令行工具和 `libimobiledevice`（`brew install libimobiledevice`）。
2. 用数据线连接并信任测试真机，确认 debug 包会输出 `sensor statitic -- event:` 日志。
3. 在本目录运行 `python3 server.py`，打开 `http://127.0.0.1:8766`。USB 采集默认只读取 `ktv` 进程日志。
4. 选择设备并开始采集，然后操作手机。也可以导入从 Xcode 控制台保存的 `.log` 或 `.txt` 文件。

环境标识为 `local-test`，本地测试数据写入 `data/local-test/events.sqlite3`，服务仅监听 `127.0.0.1`。界面及导出会遮罩常见账号和凭据字段，但本地 SQLite 保存原始日志，使用时按测试数据管理。

规则在所有会话间复用。采集中尚未命中的规则显示“待定”，停止后显示“失败”。时间间隔规则对没有可信时间戳的导入日志显示“无法判定”。每次会话最多保存 100,000 行，导入文件最大 10 MB。

事件流左侧主输入框按事件名筛选，多个事件名用 `/` 分隔；右侧“日志关键词”输入框用于普通文本搜索。日志默认按时间倒排，可切换为正排；桌面端可拖动会话、事件流和详情之间的分隔线调宽。右侧详情顶部提供属性名和属性值过滤，仅作用于当前事件详情，不减少事件列表。属性名支持包含式模糊匹配，多个名称用 `/` 分隔；属性值可单独按包含关系匹配。匹配属性显示在最上方，其余属性默认展开。规则可导入导出 JSON；统计与事件可导出脱敏 CSV/JSON。

“清除所有事件日志”在确认后删除本机 `local-test` 所有会话中的事件和运行日志，重置会话计数，保留会话和规则；采集中或只读页面不能清除。

已有采集服务正在运行时，可设置 `IOS_EVENT_LAB_PASSIVE=1 IOS_EVENT_LAB_PORT=8767` 启动第二个本机页面，共享原会话数据并实时筛选；第二个页面不控制设备采集。原页面停止采集后，重启主服务即可在默认端口使用全部新功能。
